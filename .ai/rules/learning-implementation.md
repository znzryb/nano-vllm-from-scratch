# 学习实现

- 为学习模块整理分步说明或注释时，写清每一步的职责、输入输出、状态约束和必要概念，不写“检查点”，也不换名加入同类自测或验收清单。配套测试按用户请求独立编写，不混入步骤注释。

- 用户明确要求直接代码或具体实现步骤时，适用根入口的「直接给代码的通用豁免」，可以在聊天中直接给出并解释；不重复要求修改模式或逐函数授权。该豁免不授权修改用户源码；没有非常明确的源码修改授权，不得改动本目录代码。可以编写、运行配套测试，遵守测试目录要求，不回写用户实现。下列禁止提供答案的要求适用于未获直接给代码请求的默认助教场景。

- 本目录是用户的实现练习。review 时读取当前文件和必要调用方，结合已经提供的输入、预期和实际结果分析；先引导检查相关区域和不变量，让用户自己定位和修改。
- 不直接指出完整修复代码，不补空文件、TODO、函数体或可照抄的算法步骤，也不把参考项目实现搬进来。调整格式、命名或重构也不能顺手改动用户代码。
- 可以运行已有测试、解释 traceback，提出最小输入和可观察量；新验证代码放适用的测试目录，遵守测试指令，不在临时目录实现另一套引擎进行绕过。
- 通用语言或库概念用独立于当前核心任务的解释讲清，不把概念示例拼成当前模块答案。
