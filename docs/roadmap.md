# 从零到一实现路线

每阶段先完成正确性验证，再进入性能优化。下面是计划，未勾选的内容尚未实现。

## 0. 仓库与实验约定

- [x] 建立独立仓库、Python 包和开发环境约定。
- [x] 定义阶段目标与性能报告要求。

## 1. 最小单请求推理

- [ ] 选定一个小型 decoder-only 模型和固定版本权重。
- [ ] 实现权重加载、模型前向、位置编码和 greedy decoding。
- [ ] 对比参考实现的 logits 与输出，说明浮点误差容限。
- [ ] 建立可运行示例，明确停止条件与上下文长度限制。

验收：单请求能正确生成 token，关键算子与完整前向均有参考结果。

## 2. KV cache 与静态批处理

- [ ] 实现 KV cache，区分 Prefill 与 Decode。
- [ ] 实现变长请求的静态批处理和完成请求处理。
- [ ] 覆盖缓存边界、不同长度和批次变化的正确性。
- [ ] 建立未优化基线，测量吞吐、显存和阶段耗时。

验收：缓存与无缓存路径在约定容限内一致，完整记录首组基准。

## 3. 动态调度与分页缓存

- [ ] 实现请求状态、continuous batching 和 token 预算。
- [ ] 实现分页 KV cache、分配与回收。
- [ ] 覆盖显存不足、抢占重算、请求完成与资源泄漏。
- [ ] 实现 chunked prefill，再评估 Prefill/Decode 混合批次。

验收：混合长度及动态到达负载下正确运行，明确吞吐与延迟的权衡。

## 4. 基于 profiling 的性能优化

- [ ] 保存 CPU/GPU 时间线，识别瓶颈及其占比。
- [ ] 根据证据选择缓冲区复用、元数据传输或 CUDA Graph 等优化。
- [ ] 根据负载需要评估前缀缓存与缓存驱逐策略。
- [ ] 每次只引入一项主要变量，记录收益与退化场景。

验收：可复现的前后对照、原始数据、正确性检查和性能解释。

## 5. 上游贡献

- [ ] 在目标上游重新确认问题、维护活跃度和已有 issue/PR。
- [ ] 选择维护者认可且范围集中的改进。
- [ ] 在上游环境独立复现与验证，提交符合项目要求的 PR。
- [ ] 如实记录提出、review、合并等状态，区分学习实现与上游贡献。

## 后续按需扩展

量化、投机解码、Tensor Parallel、多机与 Prefill/Decode 分离按实际选题展开，不作为首个可用版本的前置条件。
